# PRD — AI 狼人杀（ai-werewolf）

> 版本 v1.0 · 2026-09-13 · 用途：求职作品集项目（vibe coding / AI 应用工程师岗）
> 游戏规则的唯一实现依据见 `docs/RULES.md`，两者冲突时以 RULES.md 为准。

## 1. 背景与目标

用 3 周（每天 3~4 小时）做出一个上线可玩的 AI 游戏，证明三件事：

1. 能用 AI 工具独立交付完整产品（前端 + 后端 + 数据库 + 部署）
2. 能驾驭 LLM 的不确定性（结构化输出、信息隔离、评测）
3. 有线上可访问、面试官想玩的作品

## 2. 用户与场景

- **面试官 / 演示对象**：打开链接，1 分钟内理解玩法，能当场玩或看 AI 回放
- **普通玩家**：想和"会撒谎的 AI"玩狼人杀的人

## 3. 用户故事

- 作为玩家，我打开网页点一下就能开局，不用注册
- 作为玩家，我抽到狼人时要在夜里选刀口、白天伪装发言不被投出去
- 作为玩家，我抽到预言家时要决定什么时候跳身份报查验
- 作为玩家，我死后能旁观 AI 打完全局
- 作为观众，我想看纯 AI 对局的回放，看它们怎么互撕

## 4. 功能需求（MVP，P0）

| 编号 | 功能 | 说明 |
|---|---|---|
| F1 | 一键开局 | 随机座位与身份，1 人类 + 6 AI，无需登录 |
| F2 | 夜晚阶段 | 狼人击杀（人类是狼→人选目标，AI 队友给建议；全是 AI→共同决策）；预言家查验 |
| F3 | 白天发言 | 按规则顺序轮流发言，AI 流式逐字上屏；人类输入文本，可跳过 |
| F4 | 投票 | AI 并行投票（目标 + 一句理由，结构化输出）；人类点选；平票 PK 流程 |
| F5 | 胜负与结算 | 结算画面公布全部身份与过程回放 |
| F6 | 对局记录与回放 | 每局落库；回放页逐条还原对局过程 |
| F7 | 移动端可用 | 手机浏览器可完整玩一局 |

## 5. 亮点功能（P1，时间够再做）

| 编号 | 功能 | 说明 |
|---|---|---|
| F8 | AI vs AI 自动对局 + 行为评测 | 无人自动跑 20 局，统计狼人伪装存活率、好人正确投票率、局时长，落成报表 |
| F9 | 成本看板 | 每次调用记录 model/tokens/耗时；展示模型路由策略与一局成本 |
| F10 | TTS 配音 | AI 发言带语音（edge-tts 免费） |
| F11 | Dify 工作流版 | 用 Dify/Coze 复刻夜晚决策，面试对比"低代码 vs 代码开发" |

## 6. 明确不做

- 多人在线联机（免掉 WebSocket 实时同步）
- 用户注册/登录、皮肤/道具/商城
- 猎人/女巫/守卫/警长竞选等复杂板子
- 语音输入、移动 App

## 7. 非功能需求

- 一局总时长 ≤ 5 分钟；AI 单条发言 ≤ 80 字
- 单节拍 API（一次 step 请求）P95 < 15s
- LLM 输出不可靠时游戏**永不卡死**：JSON 校验 + 重试（≤2 次）+ 规则引擎兜底
- 成本：免费模型为主（glm-4-flash），决策类调用可路由到更强模型；一局成本可量化
- 部署：国内网络可直接访问（给面试官看的链接）

## 8. 验收标准

1. 人类三种身份（狼人/预言家/村民）都能完整玩到终局，无卡死
2. 连续 10 局自动对局 0 卡死、0 违规输出穿透（违规输出必须被校验拦截或兜底）
3. 回放完整还原任意一局的全部事件
4. 面试官手机打开链接可玩
5. 规则引擎单元测试覆盖全部胜负/平票/遗言边界
